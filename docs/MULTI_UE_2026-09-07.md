# 多终端、APN 与标准 API / Multi-UE, APN and standard API

## 根因与边界 / Findings and scope

1. **原 EPC 并非仅支持一台 UE。** 原 `/api/v1/ue` 从日志取单条数据，既不表示当前在线集合，也可能跨设备拼接；srsRAN 的 eNB 编译上限为 64 个 UE，但无线带宽、USB、CPU 和调度约束决定实际吞吐与并发能力。本次不宣称完成 64 台实机压测。
   **The EPC was not inherently single-UE.** The old singleton API parsed logs rather than an authoritative current set and could mix devices. The eNB compiled limit is 64, not a throughput or concurrency guarantee; RF bandwidth, USB, CPU and scheduling still constrain capacity. No 64-device hardware load test is claimed.
2. **APN 放行确有缺陷。** 旧 NAS 路径忽略显式请求 APN，GTP-C 总使用配置 APN。本次在创建会话前统一检查初始请求、ESM Information Response 及额外 PDN 请求。显式错误 APN 拒绝；省略 APN 选择默认；匹配不区分大小写。手机中 APN 配置的“名称”只是显示标签，实际 APN 字段才参与协议匹配。
   **The APN acceptance defect was real.** NAS ignored the requested APN while GTP-C used the configured APN. A shared pre-session policy now covers initial requests, ESM information responses and additional PDN requests. Wrong explicit APNs are rejected, omission selects the default, and comparison is case-insensitive. A handset's profile display name is not its protocol APN.
3. **重复连接会耗尽动态池。** 修复删除/替换会话时的 IP 回收和分配失败；ECM idle 仍保留会话地址。GTP-U 在写入 TUN 前验证 TEID 与分配地址，降低跨 UE 源地址冒用风险。
   **Reconnects could exhaust the dynamic pool.** Session deletion/replacement now reclaims addresses and allocation failure is handled explicitly. ECM idle retains the session address. GTP-U validates the assigned source address against its TEID before writing to TUN.

## 新的操作流程 / New workflow

- 所有服务端接口使用 `/api/v1`；旧根路由和 `/api/v1/ue` 返回标准 404，没有兼容别名。
  All server endpoints use `/api/v1`; old root routes and `/api/v1/ue` return the standard 404 envelope without aliases.
- `GET /api/v1/ues` 取得同一代 EPC 的当前集合；`GET /api/v1/ues/{imsi}` 按完整 IMSI 查询。保留 IMSI 前导零。缺失/过期/无效快照不伪装成空的在线集合。
  Read the current EPC generation with `GET /api/v1/ues`, and query a full IMSI using `/api/v1/ues/{imsi}`. Leading zeroes are retained; missing, stale or invalid snapshots are not presented as an authoritative empty set.
- `GET /api/v1/subscribers` 是配置卡库，不是“在线设备”。新增、修改、删除、批量替换与写卡操作先 `DELETE /api/v1/cell`，修改完成再启动。已有 SQN 从停止后磁盘版本保留；密钥不进入响应。
  Subscribers are provisioned records, not online devices. Stop the cell before create/update/delete, bulk replacement or SIM programming, then restart. Preserve existing SQNs from the stopped on-disk database; never return authentication keys.
- 重启优先 `POST /api/v1/cell` 加 `{}`，继承当前 profile。仅在有意改变网络时提交相应字段，避免 Postman 样例覆盖 DNS、频段和上行接口。
  Prefer `POST /api/v1/cell` with `{}` to reuse the current profile. Submit network overrides only intentionally, avoiding example requests that overwrite working DNS, band or uplink settings.
- 用新版集合重新导入 Postman；删除旧导入的集合，导入并不会自动删除历史分组。破坏性请求不要放入无人值守全量 Runner。
  Reimport the new Postman collection and delete the old imported collection yourself; imports do not automatically remove previous folders. Do not include destructive requests in unattended full-collection runs.

完整字段、响应状态与错误码以 [API](API.md)、[OpenAPI](api/openapi.yaml) 和 [Postman](../postman/README.md) 为准。
See [API](API.md), [OpenAPI](api/openapi.yaml) and [Postman](../postman/README.md) for exact schemas, states and errors.

## 网络划分 / Network partitioning

- `ue_subnet`: 规范的 RFC1918 IPv4 `/24`，默认 `172.16.0.0/24`；SGi 网关 `.1`，可用终端地址 `.2` 到 `.254`。启动检查当前容器网络接口的地址重叠和现存静态分配。
  A canonical RFC1918 IPv4 /24, default `172.16.0.0/24`; SGi uses `.1`, with `.2`–`.254` available to UEs. Startup validates overlap against current container interfaces and existing static assignments.
- `ue_access:"isolated"` 是默认 **UE 间隔离**；`"allow"` 允许 UE 间路由。两者都保留上行 NAT、回程和 MSS 规则，并让生命周期自有 SGi→SGi 策略处于正确顺序。
  The default `isolated` policy blocks **UE-to-UE forwarding**; `allow` permits it. Both retain uplink NAT, return traffic and MSS rules, with the lifecycle-owned SGi-to-SGi policy in the required order.
- **这不是完整“仅公网”防火墙。** 本策略不隔离 UE 与 EPC 本机服务、API、宿主机或上游 LAN；也不扫描宿主机/VPN 的所有路由。若需要这些边界，须另行设计 INPUT/上行 ACL 与管理网络。
  **This is not a complete Internet-only firewall.** It does not isolate UEs from EPC-local services, the API, host or upstream LAN, and does not inspect all host/VPN routes. Those boundaries require separate INPUT/uplink ACLs and management-network design.
- 当前为一个 APN、一个 UE 池；不支持每组独立 APN/VLAN/子网、每 UE 限速或多默认承载。API 创建/修改地址仅开放动态分配，既有静态地址保留读取和启动校验。
  There is one APN and one UE pool, not per-group APNs/VLANs/subnets, per-UE rate limiting or multiple default bearers. API address provisioning is dynamic-only; existing static addresses remain readable and are validated at startup.
- GTP-U 支持当前一体化 srsenb 的基础 GTPv1-U 包头；未宣称兼容外接 eNB 的可选扩展链。
  GTP-U supports the integrated srsenb base GTPv1-U header; external-eNB optional extension chains are not claimed as supported.

## 状态可信度 / State reliability

EPC 的控制线程生成 `ue-sessions.json`，同目录 0600 原子替换并每秒刷新。Go 校验 schema、完整 JSON、大小、进程 PID、随机 run ID、时间、会话/IMSI/IP 唯一性和上下文状态；文件不进入镜像源包或 git。注册且 ECM idle 不等于离线；承载 active 不等于实际 Internet 检测通过；未知状态必须保留未知。

The EPC control thread writes `ue-sessions.json` through same-directory 0600 atomic replacement with a one-second heartbeat. Go validates schema, complete JSON, bounds, PID, random run ID, timestamps, session/IMSI/IP uniqueness and states. Snapshots are excluded from source archives and git. Registered with ECM idle is not offline; an active bearer is not proof of Internet reachability; unknown states remain unknown.

### 可复现内核测试 / Reproduce the kernel test

先在服务器源码目录构建测试二进制（或仅在开发机交叉编译）；然后只在以下独立命名空间执行。测试会校验 namespace 仅有 loopback，并默认跳过未显式启用的运行。
Build the Linux test binary on the server (or cross-compile it on the development machine), then use only this disposable namespace. The test requires an initially loopback-only namespace and skips unless explicitly enabled.

```bash
GOOS=linux GOARCH=amd64 go test -c -o /tmp/lte-kernel-network.test ./internal/lte
docker run --rm --network none --cap-drop ALL --cap-add NET_ADMIN \
  --device /dev/net/tun --sysctl net.ipv4.ip_forward=1 \
  -e LTE_KERNEL_NETWORK_TEST=1 \
  --mount type=bind,src=/tmp/lte-kernel-network.test,dst=/test/network.test,readonly \
  --entrypoint /test/network.test IMAGE \
  -test.run '^TestKernelUENetworkPolicy$' -test.v -test.timeout 60s
```

`IMAGE` 使用本项目已构建的 runtime 镜像；没有挂载业务数据或 USB，不启动 EPC/eNB。这里的 `NET_ADMIN` 仅服务于测试 namespace，不代表生产镜像已完成最小权限迁移。
Use the project's built runtime image for `IMAGE`. No production data/USB is mounted and no EPC/eNB is started. NET_ADMIN here is scoped to the test namespace; it does not claim that production least-privilege migration is complete.
